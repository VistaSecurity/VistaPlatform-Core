ADMIN PLANE
{{- if not $adminHost }}

  NOT ISOLATED — tls.adminDnsName is unset, so the admin console and the
  cross-tenant platform-admin API are served on {{ $publicHost }} alongside the
  tenant app, reachable by anyone who can reach that host. Their platform-admin
  role check is the ONLY control on them.

  Give the admin console its own hostname (e.g. admin.{{ $publicHost }}) to move
  that API off the public host, then restrict it by source network:
    tls.adminDnsName=admin.{{ $publicHost }}
    adminPlane.ipAllowList.enabled=true
    adminPlane.ipAllowList.sourceRange={<your operator CIDR>}
{{- else if not .Values.adminPlane.restrictToAdminHost }}

  SPLIT DISABLED — adminPlane.restrictToAdminHost is false, so the
  platform-admin API remains reachable on the public host {{ $publicHost }} as
  well as on {{ $adminHost }}. Turn it back on unless something outside your
  operator network must call that API on the tenant host.
{{- else if not .Values.adminPlane.ipAllowList.enabled }}

  The platform-admin API is served on {{ $adminHost }} only; {{ $publicHost }}
  returns 404 for it.

  NO NETWORK CONTROL — adminPlane.ipAllowList is off, so anyone who can resolve
  and reach {{ $adminHost }} reaches the admin login page and the whole admin
  API. A hostname is not an access control. Restrict it to your operator
  networks:
    adminPlane.ipAllowList.enabled=true
    adminPlane.ipAllowList.sourceRange={<your operator CIDR>}
    # behind a load balancer, also set ipStrategy.depth — see values.yaml
{{- else }}

  Isolated: platform-admin API on {{ $adminHost }} only ({{ $publicHost }} returns
  404 for it), restricted to {{ join ", " .Values.adminPlane.ipAllowList.sourceRange }}.

  Verify from an address OUTSIDE that range — a check that cannot fail is
  worse than no check. If Traefik sits behind a load balancer and
  ipAllowList.ipStrategy.depth is wrong, the allow-list matches the balancer's
  own address and admits everyone while appearing to work:

    curl -s -o /dev/null -w '%{http_code}\n' https://{{ $adminHost }}/api/v1/admin-service/admin/auth/me
      expect 403 from outside the range, 401 from inside it
{{- end }}
{{- end }}

ENCRYPTED INTERNAL TRANSPORT IS ON (serviceMtls.enabled=true — default since #965)

  In-cluster traffic (gateway→backend, service-to-service{{ if .Values.datastores.postgres.tls.enabled }}, Postgres{{ end }}{{ if .Values.datastores.nats.tls.enabled }}, NATS{{ end }}) is
  mTLS-encrypted with per-service certs off a private Platform CA.

  REQUIRED cluster prerequisites (this chart does NOT install them):
    - cert-manager v1.13+  — issues the Platform CA + per-service certs.
      The install fails fast if its CRDs are missing.
    - Stakater Reloader    — restarts pods when a cert auto-rotates. The
      install does NOT fail without it, but ~60 days from now the first cert
      renewal will silently break mTLS if Reloader is absent. Verify it now:

        kubectl get deploy -A -l app.kubernetes.io/name=reloader

  To turn encrypted internal transport OFF (only for a cluster that cannot
  provide the prerequisites), set all three to false:
    serviceMtls.enabled=false
    datastores.postgres.tls.enabled=false
    datastores.nats.tls.enabled=false
{{- end }}

  Signing is keyless, so there is no key to trust: the signing identity IS
  the release workflow named in the regexp above.

{{- if .Release.IsUpgrade }}

UPGRADE NOTES

  - BACK UP THE DATABASE FIRST. This chart has no migration runner and no down
    migration: every upgrade re-applies the whole schema under
    `psql -v ON_ERROR_STOP=1`. That is deliberate (it makes skipping versions
    safe), but it means a schema statement that your data does not satisfy
    stops the migration Job partway, and the only way back is a restore.
{{- if .Values.datastores.postgres.enabled }}

      kubectl -n {{ .Release.Namespace }} exec postgres-0 -- \
        pg_dump -U {{ .Values.datastores.postgres.user }} -d {{ .Values.datastores.postgres.db }} \
        > vistaplatform-backup.sql
{{- else }}

    You are running an external database — take the snapshot with your
    provider's tooling (e.g. an RDS snapshot) before proceeding.
{{- end }}

    Afterwards, confirm which release wrote the schema. Run against your
    database:

      SELECT app_version, chart_version, applied_at
        FROM schema_migration_status ORDER BY applied_at DESC LIMIT 1;

    Quote that output in any upgrade bug report — it is the fastest way to
    tell which schema the database is actually on.

  - Use `helm upgrade --reset-then-reuse-values` for cross-version upgrades.
    `--reuse-values` carries the previous release's user-supplied image.tag
    forward verbatim, which silently pins new pods to old image bytes — the
    chart bumps, the running code does not, and helm reports success.

  - Changing any value that lands in the app ConfigMap (tls.dnsName,
    appConfig.*, ...) rolls every backend Deployment: the pod templates hash
    the rendered ConfigMap (checksum/config), because env vars are injected at
    pod start only and running pods would otherwise silently keep the old
    config. On a single-node cluster, mind the rolling-upgrade CPU-surge
    caveat in the deployment guide before making config-only upgrades.

  - For other edge-case upgrade scenarios (env-shape migrations, RWO PVC
    deadlocks), see "Upgrade" in the deployment guide:
    docsv4/core/operate/deployment/rke2-v1/deployment-guide.md
{{- if .Values.serviceMtls.enabled }}

  - ENCRYPTED INTERNAL TRANSPORT is now ON by default (#965). If you are
    upgrading a release that previously ran with all three toggles OFF, do
    NOT let this single upgrade flip them all at once. Stage it:
      1. helm upgrade with serviceMtls.enabled=true only (postgres/nats TLS
         still false) — provisions the Platform CA + per-service certs.
      2. a later helm upgrade enabling datastores.postgres.tls.enabled and
         datastores.nats.tls.enabled.
    Toggling postgres.tls on a live release recreates the schema-migration
    Job (the former #421 immutability bug is fixed by #983). See
    deployment-guide §5E. To keep the prior all-off posture on this release,
    set all three toggles to false in your values.
{{- end }}
