# Configuration and Log File Locations

## 📁 Overview

This document describes where the Crypto Inventory Network Sensor stores its configuration files, logs, and data files across different operating systems.

## 🔧 Configuration Files

### Interactive Configuration File

**Location**: `{DATA_PATH}/sensor-config.yaml`

**Purpose**: Persistent configuration created by the interactive setup mode (`-interactive` flag).

**Example locations by OS**:

- **Windows**: `C:\Users\{username}\AppData\Local\CryptoSensor\sensor-config.yaml`
- **Linux**: `/var/lib/crypto-sensor/sensor-config.yaml`
- **macOS**: `~/Library/Application Support/CryptoSensor/sensor-config.yaml`

**Contents**:

```yaml
# Crypto Inventory Network Sensor Configuration
# Generated by interactive configuration

sensorId: "00000000-0000-0000-0000-000000000000"
controlPlaneUrl: https://vista.example.com
registrationKey: REG-0000000000000000000000000000000  # from Operations → Sensors → Add sensor
reportingIntervalSeconds: 30

storage:
  maxStorageSize: 104857600    # 100 MB
  rotationSize: 10485760       # 10 MB
  retentionDays: 7
  dataPath: "C:\\Users\\username\\AppData\\Local\\CryptoSensor"
  encryptionKey: ""

capture:
  interfaces:
    - "\\Device\\NPF_{7966E225-81D5-4060-B4FD-DC13A86D60B3}"
  activeProbing: true
  networkDiscovery: true
  maxConnections: 1000
  timeoutSeconds: 30
  bufferSize: 1048576         # 1 MB

testMode: false

# mTLS Certificate Configuration (auto-generated after registration)
security:
  clientCertPath: "C:\\Users\\username\\AppData\\Local\\CryptoSensor\\certs\\client.crt"
  clientKeyPath: "C:\\Users\\username\\AppData\\Local\\CryptoSensor\\certs\\client.key"
  serverCACertPath: "C:\\Users\\username\\AppData\\Local\\CryptoSensor\\certs\\ca.crt"
  useTLS: true

# Environment variables (for reference)
# SENSOR_ID=00000000-0000-0000-0000-000000000000
# CONTROL_PLANE_URL=https://vista.example.com
# REGISTRATION_KEY=REG-0000000000000000000000000000000
# REPORTING_INTERVAL=30s
# DATA_PATH=C:\Users\username\AppData\Local\CryptoSensor
# INTERFACES=\Device\NPF_{7966E225-81D5-4060-B4FD-DC13A86D60B3}
# TEST_MODE=false
```

**Important Notes**:

- **Windows Paths**: All paths containing backslashes are automatically quoted and escaped (e.g., `"C:\\Users\\..."`)
- **Certificate Paths**: Added automatically after successful registration with the control plane
- **Interface Names**: Windows device paths (e.g., `\Device\NPF_{...}`) are properly quoted
- **Sensor ID**: Generated during registration if not provided
- **Security Section**: Contains mTLS certificate file paths for secure communication

### Configuration Priority

The sensor reads configuration in the following order (highest to lowest priority):

1. **Command line flags** (e.g., `-test`, `-verbose`)
2. **Environment variables** (set during interactive mode or manually)
3. **Configuration file** (future implementation)
4. **Default values** (built into the sensor)

## 📊 Log Files

### Test Mode Logs

**Purpose**: When running with `-test` flag, all discoveries and heartbeats are logged to files instead of being sent to the control plane.

**Files**:

- **Current log**: `{DATA_PATH}/test-discoveries.log`
- **Backup logs**: `{DATA_PATH}/test-discoveries.log.{timestamp}` (rotated files)

**Log format**: JSON with timestamps

```json
{
  "timestamp": "2025-09-24T23:15:30Z",
  "type": "discovery",
  "message": "Cryptographic implementation discovered",
  "data": {
    "protocol": "TLS",
    "dest_ip": "192.168.1.1",
    "port": 443,
    "confidence": 0.95,
    "sensor_id": "hostname-1234567890",
    "interface": "eth0"
  }
}
```

**Rotation**: Files automatically rotate when they reach 10MB, keeping the 5 most recent backups.

### Normal Mode Logs

**Purpose**: Standard operation logs and data storage.

**Files**:

- **Sensor log**: `{DATA_PATH}/sensor.log` - General sensor operation logs
- **Database**: `{DATA_PATH}/discoveries.db` - Encrypted discovery database
- **Cache**: `{DATA_PATH}/config.cache` - Cached configuration data

## 🗂️ Data Path by Operating System

### Windows

**Default Path**: `%LOCALAPPDATA%\CryptoSensor`

**Full Example**: `C:\Users\{username}\AppData\Local\CryptoSensor`

**Why this location**:

- User-specific (no admin rights required)
- Standard Windows application data location
- Automatically created by the sensor

### Linux

**Default Path**: `/var/lib/crypto-sensor`

**Why this location**:

- Standard Linux application data location
- Requires root/admin privileges for packet capture
- System-wide installation

### macOS

**Default Path**: `~/Library/Application Support/CryptoSensor`

**Full Example**: `/Users/{username}/Library/Application Support/CryptoSensor`

**Why this location**:

- User-specific (no admin rights required)
- Standard macOS application support location
- Automatically created by the sensor

## 📋 Complete File Structure

```
{DATA_PATH}/
├── sensor-config.yaml                    # Configuration file (interactive mode)
├── certs/                                # mTLS certificates (after registration)
│   ├── client.crt                        # Client certificate (PEM format)
│   ├── client.key                        # Client private key (PEM format, 0600 permissions)
│   └── ca.crt                            # Server CA certificate (PEM format)
├── test-discoveries.log                  # Test mode current log
├── test-discoveries.log.1234567890       # Test mode backup logs (rotated)
├── test-discoveries.log.1234567891       # Test mode backup logs (rotated)
├── test-discoveries.log.1234567892       # Test mode backup logs (rotated)
├── test-discoveries.log.1234567893       # Test mode backup logs (rotated)
├── test-discoveries.log.1234567894       # Test mode backup logs (rotated)
├── sensor.log                            # Normal mode sensor log
├── discoveries.db                        # Normal mode database
└── config.cache                          # Normal mode cache
```

### Certificate Files

After successful registration with the control plane:

- **client.crt**: X.509 certificate identifying this sensor
- **client.key**: Private key for the client certificate (secured with 0600 permissions)
- **ca.crt**: Certificate Authority certificate for validating the server

These certificates enable mTLS (mutual TLS) authentication between the sensor and control plane.

## 🔍 Finding Your Files

### Windows

1. **Open File Explorer**
2. **Navigate to**: `%LOCALAPPDATA%\CryptoSensor`
   - Or: `C:\Users\{your-username}\AppData\Local\CryptoSensor`
3. **Look for**:
   - `sensor-config.yaml` (configuration)
   - `test-discoveries.log` (test mode logs)

### Linux/macOS

1. **Open Terminal**
2. **Navigate to data directory**:

   ```bash
   # Linux
   cd /var/lib/crypto-sensor
   
   # macOS
   cd ~/Library/Application\ Support/CryptoSensor
   ```

3. **List files**:

   ```bash
   ls -la
   ```

## 🛠️ Custom Data Path

You can override the default data path using environment variables:

```bash
# Windows
set DATA_PATH=C:\MyCustomPath\CryptoSensor
crypto-sensor-windows-amd64.exe -test -verbose

# Linux/macOS
export DATA_PATH=/my/custom/path
./crypto-sensor -test -verbose
```

## 📝 Log Analysis

### Test Mode Log Analysis

Test mode logs are in JSON format, making them easy to analyze:

```bash
# Count discoveries by protocol
grep '"type":"discovery"' test-discoveries.log | jq '.data.protocol' | sort | uniq -c

# Find high-confidence discoveries
grep '"type":"discovery"' test-discoveries.log | jq 'select(.data.confidence > 0.9)'

# View recent discoveries
tail -f test-discoveries.log | jq '.'
```

### Log Rotation

Test mode logs automatically rotate when they reach 10MB:

- Current log: `test-discoveries.log`
- Backup 1: `test-discoveries.log.1234567890`
- Backup 2: `test-discoveries.log.1234567891`
- ... (up to 5 backups)

Old backups are automatically deleted when more than 5 exist.

## 🚨 Troubleshooting

### Configuration Not Persisting

**Problem**: Configuration is lost after closing the command prompt.

**Solution**:

1. Ensure the data directory is writable
2. Check that `sensor-config.yaml` was created
3. Verify the file contains your settings

### Log Files Not Created

**Problem**: No log files are appearing in the data directory.

**Solution**:

1. Check data path permissions
2. Ensure the sensor is running in test mode (`-test` flag)
3. Verify the data directory exists and is writable

### Large Log Files

**Problem**: Log files are taking up too much disk space.

**Solution**:

- Test mode logs automatically rotate at 10MB
- Normal mode logs should be monitored and rotated manually if needed
- Consider adjusting the `maxStorageSize` setting in configuration
