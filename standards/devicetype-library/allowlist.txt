# The device-type SEED SUBSET (DCIM DATA_MODEL §10; BUILD_PLAN row 2.2).
#
# One pattern per line, matched (path.Match) against `<Manufacturer>/<file name
# without extension>` under the library's device-types/ directory. Every
# pattern must match at least one file. The matched files are copied into
# device-types/ beside this list by
#
#   go run ./tools/devicetype-import -library <devicetype-library checkout> -commit <sha>
#
# and `make generate` renders them into scripts/database/seed.sql's
# "device-type seed subset" region (`make audit` runs it with -check).
#
# Manufacturers are seeded from the library subset AND from the OUI registry's
# canonical vendor list (shared/ouiregistry, standards/oui/vendors.yaml).
# `alias <library manufacturer> = <OUI vendor>` names a library manufacturer
# the OUI registry spells differently, so the two do not become two
# manufacturers (the library name wins; the OUI name is kept in
# external_ids.oui_vendor). `exclude-oui <vendor>` drops an OUI "vendor" that
# is not a hardware manufacturer (a hypervisor's or container runtime's
# locally administered prefix).
#
# The choice: the estate the planning documents name — Cisco
# Catalyst 9200/9300/9500 and Nexus 9300, Arista 7050/7280, Juniper
# EX4300/EX4400/QFX5120/SRX300, FortiGate 60F–600F, Palo Alto PA-220–PA-3400,
# F5 BIG-IP i-series, Ubiquiti USW/UDM/U6, Dell PowerEdge R6x0/R7x0, HPE
# DL360/DL380, Supermicro 1U/2U and APC AP7xxx/AP8xxx PDUs — the common models
# of each family rather than every SKU variant (the -TAA, -DC, -E, -R airflow
# twins are left to a tenant import).
